## 二、基础知识

### MyBatis-Plus 分页查询

MyBatis-Plus 的分页不需要手写 LIMIT SQL！只需要传一个 `Page` 对象。

> 🧠 **思考**：你需要一个 `Page<User>` 对象。它的构造函数需要什么参数？
> - 第几页（从 1 开始）
> - 每页多少条
>
> 然后调用 `userMapper.selectPage(page, 条件)` → MyBatis-Plus 自动在 SQL 后加 LIMIT。
>
> `page.getRecords()` → 当前页数据
> `page.getTotal()` → 总条数
> `page.getPages()` → 总页数

### LambdaQueryWrapper

比普通 QueryWrapper 更安全——字段名用 Lambda 表达式，IDE 自动检查：

```java
// ❌ 普通 QueryWrapper（字段名写错了不报错，运行时才发现）
new QueryWrapper<User>().like("ussername", keyword);  // 拼错了！

// ✅ LambdaQueryWrapper（编译期检查）
new LambdaQueryWrapper<User>().like(User::getUsername, keyword);  // IDE 自动提示
```

> 🧠 **思考**：你项目里的搜索需求是什么？用户输入 keyword，应该搜索哪些字段？只搜 username？还是也搜 nickname？

### RESTful 状态切换接口

```
启用用户: PUT /admin/users/1/enable   → status = 1
禁用用户: PUT /admin/users/1/disable  → status = 0
```

> 🧠 **思考**：为什么用 PUT 而不是 POST？PUT 语义是"修改已有资源"，POST 是"创建新资源"。

### 子任务 2: 完成 AdminController

**文件**: `controller/AdminController.java`（骨架已生成）

#### Part A: 用户列表（分页 + 搜索）

> 🧠 **引导**（按顺序解决）：
>
> **问题 1**：`Page<User>` 怎么创建？
> - 提示：`new Page<>(pageRequest.getPage(), pageRequest.getSize())`
>
> **问题 2**：怎么加搜索条件？
> - 提示：`LambdaQueryWrapper<User>().like(User::getUsername, keyword)`
> - 如果没有 keyword（null 或空字符串），要不要加 like 条件？
>
> **问题 3**：分页参数需要校验吗？
> - page < 1 怎么办？
> - size > 100 怎么办？（防止恶意请求拉取全部数据）
>
> **问题 4**：返回格式是什么？
> - 建议返回 `{records, total, size, current, pages}` —— 前端分页组件需要这些字段。

#### Part B: 用户状态切换

> 🧠 **引导**：
>
> 1. `@PathVariable Long id` 拿到用户 ID
> 2. `userMapper.selectById(id)` → 判断 null → 用户不存在
> 3. 修改 status → `userMapper.updateById(user)`
> 4. 两个操作（enable 和 disable）是写两个方法还是合并在一个方法里？
>    - 写两个方法更清晰，每个方法职责单一
> 5. 权限校验：学习阶段先跳过，但知道这个点——不是谁都能禁用用户！
