## Task 1: 语义缓存 L2 写入

**难度**: ⭐ | **文件**: `SemanticCacheService.java` | **时间**: 30-60 分钟

### 你要做什么

`SemanticCacheService.put()` 方法（第 122 行）有一个 TODO，需要你把 LLM 的回答写入向量库，这样以后有人问类似的问题就能命中缓存。

### 概念讲解

#### 什么是语义缓存？

先思考一个问题：用户 A 问"怎么学 Java"，用户 B 问"Java 如何学习"。这两个问题**字面上不同**，但**意思完全一样**。

- **传统缓存（L1）**: 用 `Map<String, String>`，问题作为 key。上面两个问题是不同的 key → 缓存不命中。
- **语义缓存（L2）**: 把问题转成向量（一串数字），用余弦相似度比较。意思相近的问题 → 向量距离近 → 缓存命中。

这就是 **GPTCache** 的核心思想。

#### Spring AI 的 Document 是什么？

`Document` 是 Spring AI 里最基本的数据单元，它有两个核心部分：

```
Document {
    String text;        // 文档的文本内容（用于生成向量/embedding）
    Map<String, Object> metadata;  // 元数据（附带的标签、分类等，不参与向量计算）
}
```

**关键理解**: `text` 会被转成向量用于相似度搜索，`metadata` 不会被向量化，只是附带信息。

#### VectorStore 怎么存？

```java
// 伪代码 — 展示概念，不是让你复制
Document doc = new Document("文本内容", Map.of("key", "value"));
vectorStore.add(List.of(doc));
// 向量库会自动把 doc.text 转成向量存起来
```

#### 缓存 L2 写入的逻辑

1. 把用户问题（query）作为 Document 的 `text`（用于以后做相似度匹配）
2. 把 LLM 回答（answer）放进 `metadata`（以后匹配到了就取出来返回）
3. 调用 `vectorStore.add()` 写入

**关键问题**: 为什么把 query 作为 text 而不是把 answer 作为 text？

因为以后做相似度搜索时，是用**新问题**去匹配**旧问题**。如果 text 是旧问题的文本，新问题和旧问题意思相近时，向量距离就小，就能匹配到。

> 不要急着写代码，先回答这些问题：

1. `Document` 的构造函数接收哪两个参数？它们的类型分别是什么？
2. 查看 `semanticSearch()` 方法（第 142 行），读缓存时从 metadata 里取的是什么 key？
3. 写入时应该用相同的 key 吗？（提示：写入和读取的 key 必须一致，否则读不到）
4. `vectorStore.add()` 需要传什么参数？是单个 Document 还是 List？

### 基础知识: Map.of() 是什么？

Java 9 提供了 `Map.of(key1, value1, key2, value2, ...)` 来快速创建不可变的 Map：

```java
// 老写法
Map<String, Object> map = new HashMap<>();
map.put("name", "张三");
map.put("age", 25);

// 新写法（更简洁，但 Map 不可修改）
Map<String, Object> map = Map.of("name", "张三", "age", 25);
```

## Task 2: 修复消息反序列化

**难度**: ⭐⭐ | **文件**: `FileBasedChatMemory.java` | **时间**: 1-2 小时

### 你要做什么

`mapToMessage()` 方法（第 178 行）只处理了 `USER` 和 `ASSISTANT` 两种消息类型。当对话中涉及工具调用时，JSON 文件里会有 `TOOL_RESPONSE` 类型的消息，但还原时被错误地当成 `AssistantMessage` 处理了。

### 概念讲解

#### Spring AI 的 Message 类型体系

Spring AI 里所有的消息都实现了 `Message` 接口。日常对话中有这几种消息：

```
Message（接口）
├── UserMessage          ← 用户说的话
├── AssistantMessage     ← AI 的回复
│   └── 包含 ToolCall 列表  ← AI 决定调用哪些工具
├── ToolResponseMessage  ← 工具执行后返回的结果
│   └── 包含 ToolResponse 列表（工具名 + 返回数据）
└── SystemMessage        ← 系统指令（不参与对话）
```

**对话的完整流程**:
```
用户: "帮我搜索AI新闻"
  → UserMessage("帮我搜索AI新闻")

AI: 决定调用搜索工具
  → AssistantMessage(包含 ToolCall: searchWeb("AI新闻"))

工具执行完毕，返回结果
  → ToolResponseMessage(包含 ToolResponse: "百度搜索结果...")

AI: 根据搜索结果生成回复
  → AssistantMessage("根据搜索结果，最新的AI新闻有...")
```

#### JSON 序列化后 ToolResponseMessage 长什么样

在 `data/chat-memory/` 目录下找一个有工具调用的对话 JSON 文件，你会发现 ToolResponseMessage 的结构类似：

```json
{
  "messageType": "TOOL_RESPONSE",
  "responses": [
    {
      "name": "searchWeb",
      "responseData": "百度搜索结果..."
    }
  ]
}
```

#### 多态反序列化问题

这是一个经典的编程问题：JSON 里用一个字符串 `"TOOL_RESPONSE"` 表示类型，但 Java 里需要创建对应的类实例。你需要根据这个字符串**判断**创建哪个类的对象。

**常见的解决模式**（if-else 类型判断）:
```
if (type == "A") → new ClassA()
else if (type == "B") → new ClassB()
else → new 默认类型()
```

## Task 3: 请求参数校验

**难度**: ⭐⭐ | **文件**: `LoginRequest.java`、`RegisterRequest.java`、`UserController.java` | **时间**: 2-3 小时

### 你要做什么

目前用户可以用空字符串作为用户名注册，密码也可以是空的。你需要给 DTO 添加校验注解，让 Spring 在请求进来时自动检查参数合法性。

### 概念讲解

#### 为什么要"提前校验"？

```
❌ 不校验（校验在业务逻辑里）:
Controller → Service → 数据库 → 发现用户名是空的 → 报错
（浪费了 Service 和数据库的调用）

✅ 提前校验（在 Controller 层就拦住）:
Controller → 发现用户名是空的 → 直接返回 400 错误
（Service 和数据库根本不会执行）
```

这个原则叫 **Fail Fast**（快速失败）：在系统边界就拦住无效数据。

#### Jakarta Bean Validation

Spring Boot 内置了 Jakarta Bean Validation（以前叫 JSR 380），是一套用注解声明校验规则的规范。

**常用注解速查表**:

| 注解 | 作用 | 示例 |
|------|------|------|
| `@NotNull` | 不能为 null | `@NotNull` |
| `@NotBlank` | 不能为 null + 不能全是空格 | `@NotBlank String name` |
| `@NotEmpty` | 不能为 null + 不能为空（字符串/集合） | `@NotEmpty List<String> items` |
| `@Size(min, max)` | 字符串长度/集合大小范围 | `@Size(min=3, max=20)` |
| `@Pattern(regexp)` | 必须匹配正则表达式 | `@Pattern(regexp="^[a-zA-Z0-9]+$")` |
| `@Email` | 必须是邮箱格式 | `@Email` |

#### @NotBlank vs @NotEmpty vs @NotNull 的区别

| 注解 | `null` | `""` | `"  "` | `"abc"` |
|------|--------|------|--------|---------|
| `@NotNull` | ❌ | ✅ | ✅ | ✅ |
| `@NotEmpty` | ❌ | ❌ | ✅ | ✅ |
| `@NotBlank` | ❌ | ❌ | ❌ | ✅ |

#### 如何触发校验

在 Controller 方法参数前加 `@Valid` 或 `@Validated`：

```java
// @Valid 会告诉 Spring："这个参数需要校验"
public ApiResponse login(@RequestBody @Valid LoginRequest request) { ... }
```

当校验失败时，Spring 自动返回 HTTP 400，不会进入方法体。

### 引导问题

1. 用户名应该用什么注解？允许 null 吗？允许空字符串吗？允许纯空格吗？
2. 用户名最短多长合适？3 个字符还是 5 个字符？（想想数据库里 username 字段的限制）
3. 密码需要校验什么？长度限制？需不需要 `@Pattern` 限制字符类型？
4. 昵称是选填的，但如果填了，要不要限制长度？
5. 注册接口有两个密码字段 `password` 和 `confirmPassword`，它们的校验规则有什么不同？
6. 你在 Controller 加了 `@Valid` 后，怎么验证它生效了？试试用 Postman 发一个空用户名请求看看。

### 基础知识: 正则表达式入门

`@Pattern(regexp = "...")` 里的字符串叫正则表达式，用来匹配文本模式：

| 正则 | 含义 |
|------|------|
| `^[a-zA-Z0-9]+$` | 只允许字母和数字，至少 1 个字符 |
| `^[a-zA-Z0-9_]{3,20}$` | 字母数字下划线，3-20 个字符 |
| `.{6,}` | 至少 6 个任意字符 |

`^` = 字符串开头，`$` = 字符串结尾，`{min,max}` = 长度范围，`+` = 至少 1 个。

### 你的挑战

1. 给 `LoginRequest` 的字段添加校验注解
2. 给 `RegisterRequest` 的字段添加校验注解（注意它有 3 个字段）
3. 在 `UserController` 的 `login()` 和 `register()` 方法参数上加 `@Valid`

✅ **完成标准**: 用空用户名调用注册接口，返回 HTTP 400 错误。

## Task 4: 全局异常处理

**难度**: ⭐⭐⭐ | **文件**: 新建 `exception/` 包 | **时间**: 4-6 小时

### 你要做什么

当前项目没有任何统一的异常处理。你需要创建：
1. 自定义异常类（至少 2 个）
2. 一个全局异常处理器

### 概念讲解

#### 为什么要自定义异常？

```java
// ❌ 不好的做法
if (user == null) {
    throw new RuntimeException("用户不存在");  // 调用方不知道这是什么异常
}

// ✅ 好的做法
if (user == null) {
    throw new ResourceNotFoundException("用户不存在");  // 调用方一看就知道
}
```

自定义异常让调用方可以**按异常类型做不同的处理**：
- `AuthenticationException` → 返回 401（没登录）
- `ResourceNotFoundException` → 返回 404（不存在）
- `BusinessException` → 返回 400（业务逻辑错误）
- 其他未知异常 → 返回 500（系统错误，需要人工排查）

#### 什么是 @ControllerAdvice？

`@ControllerAdvice` 是 Spring AOP（面向切面编程）的一个应用。

```
正常流程（无异常）:
请求 → Controller → Service → 返回数据给用户

异常流程:
请求 → Controller → Service → 抛异常 💥 → @ControllerAdvice 拦截 → 转成 JSON 错误返回
```

`@ExceptionHandler` 注解指定这个方法处理哪种异常，Spring 会**自动选择最匹配**的 handler：

```java
@ExceptionHandler(ResourceNotFoundException.class)
public ApiResponse handleNotFound(ResourceNotFoundException e) {
    // 返回 404
}

@ExceptionHandler(Exception.class)  // 兜底，处理所有没被上面匹配的异常
public ApiResponse handleGeneral(Exception e) {
    // 返回 500
}
```

**匹配规则**: Spring 会选择异常类型最接近的那个 Handler。比如抛出 `ResourceNotFoundException`，它既匹配 `ResourceNotFoundException` 的 handler 也匹配 `Exception` 的 handler，但 Spring 选**最具体**的那个。

### 基础知识: HTTP 状态码

| 状态码 | 含义 | 使用场景 |

## Task 5: DTO 与数据安全

**难度**: ⭐⭐ | **文件**: 新建 `model/dto/UserResponse.java` | **时间**: 2-3 小时

### 你要做什么

当前 `UserController.getCurrentUser()` 直接把数据库实体 `User` 返回给了前端。但 `User` 实体包含 `password` 字段（BCrypt 哈希值），这会导致密码哈希泄露。

### 概念讲解

#### Entity vs DTO — 为什么不直接返回数据库实体？

```
Entity（实体）: 和数据库表一一对应，包含所有字段
DTO（Data Transfer Object）: 只包含"需要传输"的字段

User (Entity):           UserResponse (DTO):
  id          →           id
  username    →           username
  password    →           ❌ 不传！永远不出服务器
  nickname    →           nickname
  createdAt   →           createdAt
```

**直接返回 Entity 的问题**:
1. 密码哈希泄露（安全问题）
2. 数据库表结构改了 → API 响应也变了（前端受影响）
3. 实体里可能有内部字段（如 `isDeleted`、`version`）不应该暴露

#### 如何进行对象转换？

有几种方式：

**方式 1: Getter/Setter 手动赋值**（最直观，适合新手）
```java
UserResponse resp = new UserResponse();
resp.setId(user.getId());
resp.setUsername(user.getUsername());
// password 故意不设置 → 不会泄露
```

**方式 2: Spring 的 BeanUtils.copyProperties()**（一行代码，但要注意）
```java
UserResponse resp = new UserResponse();
BeanUtils.copyProperties(user, resp);
// ⚠️ 问题：同名属性都会被复制！如果 DTO 也有 password 字段，会被复制过去
```

**方式 3: MapStruct**（编译期生成，性能最好，但需要额外依赖）

### 引导问题

1. `UserResponse` 应该包含哪些字段？哪些字段不应该出现？
2. 如果用 `BeanUtils.copyProperties()`，会有什么风险？DTO 应该包含 `password` 字段吗？
3. `UserResponse` 用 `class` 还是 `record`？（`record` 是 Java 14 的新特性，更简洁但不可变）
4. 除了 `getCurrentUser`，还有哪些地方可能泄露敏感数据？检查所有返回 `User` 的地方。

### 基础知识: Java Record

`record` 是 Java 14 引入的，专门用来做"不可变数据载体"：

```java
// 传统写法
public class UserResponse {
    private final Long id;
    private final String username;
    // 构造函数 + getter + equals + hashCode + toString
}

// Record 写法（一行搞定上面所有）
public record UserResponse(Long id, String username, String nickname) {}
```

Record 自动生成：构造函数、所有字段的 getter（方法名就是字段名）、`equals()`、`hashCode()`、`toString()`。

### 你的挑战

1. 创建 `UserResponse` 类（用 `class` 或 `record` 都可以）
2. 修改 `UserController.getCurrentUser()` 返回 `UserResponse` 而不是 `User`
3. 在 `UserServiceImpl`（或 Controller）里做 User → UserResponse 的转换
4. 验证：调用 `/api/user/me` 接口，确认返回的 JSON 里**没有 password 字段**

✅ **完成标准**: `/api/user/me` 返回的 JSON 不包含 password。

## Task 6: 敏感配置外部化

**难度**: ⭐⭐ | **文件**: `JwtUtil.java`、新建 `config/JwtProperties.java` | **时间**: 2-3 小时

### 你要做什么

当前 `JwtUtil` 用 `@Value("${jwt.secret}")` 注入单个配置项。你需要创建 `JwtProperties` 类用 `@ConfigurationProperties` 统一管理 JWT 相关配置。

### 概念讲解

#### @Value vs @ConfigurationProperties

```java
// 方式 A: @Value（一个一个注，松散）
@Value("${jwt.secret}")
private String secret;

@Value("${jwt.expiration}")
private long expiration;

// 方式 B: @ConfigurationProperties（一组配置绑定到一个类，类型安全）
@ConfigurationProperties(prefix = "jwt")
public class JwtProperties {
    private String secret;
    private long expiration;
    // getter + setter
}
```

**@ConfigurationProperties 的优势**:
1. 类型安全：如果 `expiration` 配置成字符串，启动时直接报错
2. 可校验：可以在字段上加 `@NotNull`、`@Min` 等注解
3. 结构清晰：所有相关配置在一个类里
4. IDE 有自动补全

#### 12-Factor App 原则

[12-Factor App](https://12factor.net/) 是构建云原生应用的方法论。第三条是：**"把配置存储在环境变量中"**。

原因很简单：
- 同样的代码要部署到开发/测试/生产环境
- 每个环境的配置不同（数据库密码、API Key）
- 环境变了，不改代码，只改环境变量

#### Spring 的配置优先级

Spring Boot 有一个严格的配置优先级（从高到低）：
1. 命令行参数 `--server.port=8080`
2. 环境变量 `SERVER_PORT`
3. `application-{profile}.yml`
4. `application.yml`

**这意味着**：你在 `.env` 里设的变量会自动覆盖 `application.yml` 里的值。

### 引导问题

1. `@ConfigurationProperties` 需要什么注解来激活？（提示：在 `@SpringBootApplication` 类上加什么？）
2. JWT 相关配置有哪些？把它们归纳到一个类里。
3. `@ConfigurationProperties` 的类需要 getter/setter 吗？（提示：Spring 需要 setter 来注入值）
4. 如何在 `JwtUtil` 里使用 `JwtProperties`？（提示：构造函数注入还是 `@Autowired`？）
5. `.env.template` 已经创建好了，你还需要创建什么来保护敏感信息？

### 基础知识: 构造函数注入 vs 字段注入

```java
// 字段注入（不推荐）
@Autowired
private JwtProperties jwtProperties;

// 构造函数注入（推荐：方便测试，依赖明确）
private final JwtProperties jwtProperties;

public JwtUtil(JwtProperties jwtProperties) {
    this.jwtProperties = jwtProperties;
}
```

**为什么构造函数注入更好**：
- 依赖关系在构造函数中一目了然
- 写单元测试时可以手动 new 传参，不需要启动 Spring 容器
- 字段可以是 `final`，不会被意外修改

### 你的挑战

1. 给 `YuAiAgentApplication` 加上 `@ConfigurationPropertiesScan` 注解
2. 创建 `JwtProperties` 类（注意包的位置）
3. 修改 `JwtUtil`，用 `JwtProperties` 替代 `@Value`
4. 验证：启动项目，确认 JWT 功能正常（登录 → 拿到 token → 用 `/user/me` 验证）

✅ **完成标准**: 修改 `application.yml` 中 `jwt.expiration` 的值，重启后 token 过期时间改变。

## Task 7: 从零构建 ReAct 循环

### 概念讲解

#### 什么是 ReAct？

ReAct = **Re**asoning + **Act**ing（推理 + 行动）

人类解决问题的方式：
```
问："上海今天天气怎么样？"
思考："我不知道，需要查一下" ← Reasoning
行动：打开天气网站搜索         ← Acting
观察：看到结果了
思考："结果是晴天 25°C"      ← Reasoning
行动：回答用户                ← Acting
```

AI Agent 的 ReAct 循环完全模仿这个过程：
```
while (还没完成) {
    think() → AI 思考下一步该做什么（也许要调工具）
    act()   → 执行 AI 的决定（调工具或回复用户）
}
```

#### 消息列表是 Agent 的"记忆"

```
初始: [UserMessage("搜索AI新闻")]

第 1 轮:
  think → AI 返回 AssistantMessage(含ToolCall: searchWeb)
  act   → 执行 searchWeb → ToolResponseMessage("搜索结果...")
  消息列表变成: [UserMessage, AssistantMessage, ToolResponseMessage]

第 2 轮:
  think → AI 看到搜索结果，生成 AssistantMessage("最新AI新闻有...")
  消息列表变成: [UserMessage, AssistantMessage, ToolResponseMessage, AssistantMessage]
  没有ToolCall了 → 退出循环
```

**关键**: 每轮都把**完整的消息列表**传给 AI，这样 AI 能看到之前所有的对话和工具结果。

#### 你正在构建的其实和 ToolCallAgent 一样

```
StepByStepReActTest (你将构建的)    →    ToolCallAgent (项目里的)
     Level 2: 获取ToolCall          →    think() 方法的前半段
     Level 3: 执行ToolCall          →    act() 方法
     Level 4: for循环               →    BaseAgent.run() 里的循环
     Level 5: SystemPrompt          →    YuManus 构造函数的 SYSTEM_PROMPT
```

## Task 8: 异常处理 + 安全加固

### Part A: 异常处理

#### 概念讲解

#### 为什么需要区分异常类型？

AI Agent 运行中可能遇到不同类型的错误：

| 错误类型 | 示例 | 应该怎么处理 |
|----------|------|------------|
| API 暂时不可用 | 请求超时、限流 | 重试 1 次 |
| 工具执行失败 | 文件不存在 | 告诉 AI 结果，让它换方案 |
| 代码逻辑错误 | NullPointerException | 记录日志，停止 Agent |
| 用户中断 | 客户端断开 | 清理资源 |

**你当前的代码**（ToolCallAgent.think() 第 99 行）:
```java
catch (Exception e) {
    // 所有异常都一样处理 → 无法区分
}
```

#### 重试模式

```java
// 重试 1 次的简单模板
int maxRetries = 1;
for (int attempt = 0; attempt <= maxRetries; attempt++) {
    try {
        return doSomething();
    } catch (RetryableException e) {
        if (attempt == maxRetries) throw e; // 最后一次了，不再重试
        log.warn("第{}次尝试失败，准备重试", attempt + 1);
    }
}
```

#### 引导问题（Part A）

1. 什么样的异常可以重试？什么样的异常不应该重试？
2. 重试之前要不要等一下？（提示：立即重试可能遇到同样的错误，加个 `Thread.sleep()`）
3. 当工具执行失败时，应该把什么信息告诉 AI？（提示：看 `act()` 方法中怎么构造返回结果的）
4. AI Agent 的错误状态有几种？当前只有 `ERROR` 一个错误状态，够用吗？

### Part B: 终端命令安全

#### 概念讲解

#### 为什么 TerminalOperationTool 危险？

当前代码：
```java
ProcessBuilder builder = new ProcessBuilder("cmd.exe", "/c", command);
```

这意味着 AI 可以执行**任意 Windows 命令**。如果用户通过 prompt injection 诱导 AI 执行恶意命令：
- `del /f /s /q C:\*` → 删除整个 C 盘
- `shutdown /s /t 0` → 关机
- `format C:` → 格式化 C 盘

#### 白名单 vs 黑名单

```
黑名单思路（不安全）:
"阻止 del、format、shutdown..."
→ 总有你不知道的危险命令，永远列举不完

白名单思路（安全）:
"只允许 python、dir、echo、type、findstr"
→ 除此之外一律拒绝，安全得多
```

**安全领域的黄金法则**: 默认拒绝，显式允许。

#### 引导问题（Part B）

1. 你允许哪些命令？为什么选这些？（Safe Commands：`python`、`dir`、`echo`、`type`、`findstr`、`mkdir`）
2. 怎么从用户输入的完整命令中提取"命令名"？（提示：`dir /s C:\` 的命令名是 `dir`，用空格分割取第一个）
3. 命令参数能不能也做限制？比如 `python` 允许，但 `python -c "import os; os.system('del /f C:\\*')"` 怎么办？
4. 白名单应该用什么数据结构存？（提示：`Set<String>` 的 `contains()` 是 O(1) 的）
5. 当命令不在白名单里时，给用户返回什么提示？

### 你的挑战

**Part A**: 在 `ToolCallAgent.think()` 中：
- 区分 API 调用异常和工具执行异常
- 对 API 异常重试 1 次
- 对不同的异常打印不同级别的日志（`log.warn` vs `log.error`）

**Part B**: 在 `TerminalOperationTool.executeTerminalCommand()` 中：
- 在执行命令前提取命令名
- 检查是否在白名单中
- 不在白名单 → 返回错误提示，不执行
- 在白名单 → 继续执行

✅ **完成标准**: 
- Part A: 模拟 API 异常（比如断网），Agent 会自动重试
