## 二、限流算法大白话

### 固定窗口 vs 滑动窗口

```
固定窗口（有 bug）:
  [第 1 分钟的最后一秒] ← 5 个请求
  [第 2 分钟的第一秒]  ← 5 个请求
  间隔只有 2 秒但发了 10 个请求 → 没被限流！（窗口边界问题）

滑动窗口计数器（你用的）:
  每次请求时看"过去 60 秒内来了几个请求"
  无论窗口边界在哪，都能准确限流
```

### Redis INCR 原理

`INCR key` = 给 key 的值 +1，如果 key 不存在就当 0 处理（返回 1）。

```
第 1 次: INCR rate:login:192.168.1.1 → key 不存在 → 返回 1
第 2 次: INCR rate:login:192.168.1.1 → key 存在(值=1) → 返回 2
...
第 6 次: INCR rate:login:192.168.1.1 → 返回 6 → > 5 → 拦截！
```

每次返回 1 时（首次访问），设 `EXPIRE 60` 让 key 在 60 秒后自动删除。

## 三、你的任务

### 子任务 1: 完成 RateLimitAspect

**文件**: `aspect/RateLimitAspect.java`（骨架已生成）

> 🧠 **按顺序思考，不要一次性全想完**：

**第 1 步：注入 RedisTemplate**
- 用什么方式注入？（`@Resource` 还是构造函数注入？）
- `RedisTemplate<String, Long>` 的类型参数为什么是 Long？

**第 2 步：获取注解参数**
- `rateLimit.maxRequests()` 返回什么类型？
- `rateLimit.timeWindow()` 和 `rateLimit.timeUnit()` 怎么配合使用？
  - 比如 timeWindow=60 + timeUnit=SECONDS → 60 秒的时间窗口

**第 3 步：获取客户端标识**
- 从 `HttpServletRequest` 拿 IP：`RequestContextHolder.getRequestAttributes()` → `getRequest()` → `getRemoteAddr()`
- 或者从 `UserContext.getCurrentUserId()` 拿用户 ID（更精确）
- **你选哪个？** IP 的话同一个局域网的人共用。用户 ID 的话没登录的请求没法识别。

**第 4 步：拼 Redis key**
- 格式怎么设计？提示：要能区分不同接口、不同用户/IP
- 示例思路：`rate_limit:<方法名>:<IP>`

**第 5 步：INCR 自增**
- 用什么 Redis 操作？（提示：`opsForValue().increment(key)`）
- 返回 1 说明什么？这时需要做什么？
- 返回 > maxRequests 说明什么？

**第 6 步：判断是否超限**
- 超限时返回什么？HTTP 状态码 429（Too Many Requests）

**第 7 步：Redis 异常处理**
- 整个 Redis 操作包在 try-catch 里
- catch 到异常 → 记录日志 → 放行还是拦截？
- 面试标准答案：降级放行（优先保证可用性）
