# 能力画像准确性、知识点覆盖与统一 UI 设计

## 1. 背景与目标

当前能力画像存在三个问题：

1. 面板使用红、橙、黄、绿、蓝等多种高饱和状态色和渐变，与对话页面的靛蓝、灰白视觉体系不一致。
2. 薄弱点会显示“态度敷衍”“为空或偏离主题”“基础知识点缺失”等评价词，而不是用户未掌握的知识点；少数历史数据还存在跨方向错误归类。
3. 虽已引入每方向知识维度和题目指纹，但模型输出仍可能突破当前考卷边界，造成 Java 并发下出现 MySQL 或 Redis、计算机网络下出现进程线程和 IPC 等问题。

本次目标：

- 弱项只展示可学习、可追问的具体知识点。
- 弱项严格受当前考卷方向和当前题目维度约束。
- 历史画像展示时自动过滤脏数据，不修改原始答题、分数和画像文件。
- 保留现有异步评分频率，不增加高频模型调用；开发和测试期模型 API 开销控制在 20 元人民币以内。
- 保持 16 个方向轮转和每方向 8 个维度的覆盖框架，增强后端的确定性约束。

## 2. 非目标

- 不新增图表库、外部服务或新的 LLM 调用链路。
- 不对已有 `.ability-profiles` 文件做批量覆盖或不可逆迁移。
- 不替换当前 16 个方向的轮转机制。
- 不以本地关键词评分替代 LLM 对回答质量的语义评分。

## 3. 总体方案

采用“Prompt + 后端知识边界校验 + 展示层历史清洗 + 单色 UI”方案。

评分模型继续承担回答质量判断和候选薄弱点提取；后端不信任其方向、维度和弱项文本，负责最终可落库、可展示的知识点判定。前端直接展示后端规范化后的知识点，不再用正则从评价句中猜测名称。

```text
用户回答
  -> 异步评分（一次既有 LLM 调用）
  -> 评分候选结果
  -> 当前方向 + 当前维度的后端强校验
  -> 能力画像
  -> 画像接口展示层清洗
  -> 统一靛蓝灰白能力面板
```

## 4. 后端设计

### 4.1 题目上下文

将 `QuizApp.QuestionContext` 从 `{ topic, question }` 扩展为：

```java
{ topic, dimension, question }
```

`dimension` 解析顺序：

1. 优先解析本轮 AI 回复的 `[DIM:xxx]` 标记。
2. 标记缺失时，基于当前方向内的维度关键词回退推断。
3. 仍不能确认时设为空；不得用其他方向推断结果替代。

异步评分服务接收固定的 `topic` 和 `dimension`，评分模型只能按此上下文提取候选弱项。

### 4.2 弱项规范化与校验

新增单一职责的知识点规范化组件，供新评分落库和历史展示共用。输入为方向、维度、模型候选弱项与详情，输出为已验证的具体知识点。

处理流程：

1. 丢弃空值、长度异常值、纯评价词和通用负面描述。
2. 依据方向关键词与别名映射识别跨方向项，直接丢弃。
3. 有当前维度时，仅保留与该维度关键词或别名相关的项。
4. 对合格项去重、裁剪并保留对应详情。
5. 若模型候选全部无效且当前维度可识别，以维度主体名作为安全兜底；例如“锁机制”，绝不以“回答偏离主题”作为兜底。
6. 若当前维度也无法确认，则仅更新分数，不写入弱项。

模型仍返回 `score`、`weakPoints`、`weakPointDetails`。方向始终以后端传入的当前考卷方向为准，不能采用模型声称的 `topic`。

### 4.3 历史数据展示清洗

画像查询和摘要构建时复用规范化组件：

- 返回给前端的 `weakPoints` 只包含当前方向可识别的具体知识点。
- 旧评价词、跨方向项和无效项不返回。
- 既有 `weakPointAnswers`、`weakPointDetails` 仅为仍可展示的规范化项保留映射。
- 某个方向清洗后无有效弱项时，仅展示评分与答题数。

该流程不写回原始画像文件，避免误删历史数据。

### 4.4 方向与维度边界

`TopicDimensions` 继续维护 16 个方向、每方向 8 个维度，并补充用于校验的方向关键词、别名和维度关键词。

重点边界：

| 知识点 | 唯一归属方向 |
|---|---|
| MySQL 索引失效场景 | MySQL |
| Redis 数据结构与底层实现 | Redis |
| 进程与线程区别、进程间通信（管道、消息队列、共享内存、Socket） | 操作系统与Linux |
| TCP/IP、HTTP/HTTPS、DNS、WebSocket、HTTP/2/3、网络 IO 模型 | 计算机网络 |

因此，计算机网络考卷中出现进程、线程、IPC 候选项时将被丢弃；Java 并发中出现 MySQL、Redis 候选项同样被丢弃。

### 4.5 覆盖与去重

保留以下既有能力：

- `[DIM:xxx]` 优先记录题目维度。
- 未覆盖维度优先取题。
- 题目指纹过滤重复题。
- 无标记时才使用关键词回退。

新增原则：当前考卷方向决定候选知识点的合法范围；模型不会再自由决定学科归属。

## 5. 前端设计

修改 `AbilityPanel.vue`，保持现有侧栏布局、雷达图、展开交互、刷新、重置和学习建议入口，不新增依赖。

### 5.1 视觉规范

统一采用现有对话区同系的靛蓝和灰白：

| 元素 | 样式 |
|---|---|
| 主色 | `#4f46e5` |
| 弱强调背景 | `#eef2ff` |
| 主文本 | `#1e293b` |
| 辅助文本 | `#64748b` |
| 边框 | `#e2e8f0` |
| 状态区分 | 文字、进度长度、透明度和边框层级 |

移除红、橙、黄、绿的状态圆点、彩色渐变进度条、彩色卡片底色、彩色历史评分方块与雷达图多色点。雷达图、卡片、进度和评分历史全部使用靛蓝的透明度与灰色层级。

### 5.2 信息结构

主信息结构调整为：

```text
能力画像
综合掌握度 · 已考察方向 · 总答题数

能力概览（雷达图）

需重点复习
Java并发 · 2 / 5 · 已答 3 题
未掌握：锁机制、线程池拒绝策略、JMM happens-before

已考察方向
待考察方向
```

主区块使用中性、任务导向文案：

- `需重点复习`
- `已考察方向`
- `待考察方向`

不再在主列表中使用“薄弱方向”“待加强”“掌握良好”等带状态色的分组语言。

### 5.3 知识点详情

点击知识点时展示：

```text
Java并发 · JMM happens-before

题目要求
...

你的回答
...

遗漏的关键点
...
```

“遗漏的关键点”来自后端已校验的 `weakPointDetails`。历史数据没有可用详情时显示“暂无可用的题目分析”，不回显评价性脏文本。前端移除将长评价语正则截断为知识点名称的主路径。

## 6. 容错与成本

### 容错

- 评分 JSON 解析失败：不阻塞主对话，按既有回退更新策略处理，但不写入不可信弱项。
- 模型输出评价词或跨方向内容：规范化组件丢弃。
- AI 没有输出 `[DIM]`：按当前方向的关键词回退；失败时不记录弱项。
- 历史画像结构不完整：不影响面板渲染，只降级隐藏详情。

### 成本

- 不新增模型调用次数。
- 继续使用用户回答后的一次异步评分。
- 历史数据清洗完全在本地规则中完成。
- 开发验证使用构造数据与单元测试，避免反复调用模型。
- 开发与测试期累计模型 API 成本上限为 20 元人民币。

## 7. 测试与验收

后端测试覆盖：

1. Java并发回答包含 MySQL、Redis 文本时，弱项不写入这两个知识点。
2. 计算机网络考卷中出现进程、线程、IPC 时，不记录到网络画像。
3. MySQL 索引失效场景、Redis 数据结构与底层实现等保留为具体知识点。
4. 评价性弱项被过滤；所有候选无效时，正确回退到当前维度主体名。
5. 历史脏数据读取后不出现在接口的 `weakPoints` 中。
6. `[DIM]` 标记、关键词回退和题目指纹去重不发生回归。

前端验收：

1. 能力画像不再出现彩虹式状态色或多色渐变。
2. 主列表仅展示规范化后的具体知识点。
3. 详情弹窗显示题目要求、用户回答和遗漏要点；无详情时显示中性空态。
4. 桌面端和移动端文字不溢出，折叠、刷新、重置和建议弹窗可用。
