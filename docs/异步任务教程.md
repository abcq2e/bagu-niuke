## 二、同步 vs 异步（用餐馆类比理解）

```
同步（当前模式）:
  用户点菜 → 厨师做菜 → 服务员上菜 → 用户开始吃
  厨师做菜时，服务员什么也不干，干等着 ← 浪费时间

异步（优化后）:
  用户点菜 → 厨师开始做（后台）→ 服务员去干别的
  厨师做好了 → 通知服务员 → 服务员上菜
  服务员不用干等 ← 效率更高
```

> 🧠 **思考**：在你的项目中，"厨师"是谁？"服务员"是谁？"上菜"是什么？

## 三、线程池基础知识

### 为什么不直接 new Thread？

创建线程很贵（占用内存、CPU 上下文切换）。线程池预先创建好一批线程，用完还回去，不销毁——和数据库连接池一个道理。

### 线程池的 4 个核心参数

想象线程池是一个**银行柜台**：

| 参数 | 类比 | 说明 |
|------|------|------|
| corePoolSize | 常驻柜员（一直在线） | 平时就这么多线程 |
| maxPoolSize | 最多能开几个窗口 | 忙时临时增加 |
| queueCapacity | 排队等候区 | 柜台都忙时在此排队 |
| keepAliveTime | 临时柜员空闲多久撤离 | 超过这个时间就回收 |

> 🧠 **思考——你自己决定参数值**：
> 1. 你的 CPU 有几个核心？（提示：`Runtime.getRuntime().availableProcessors()`）
> 2. Neo4j 写入是 I/O 密集型还是 CPU 密集型？
>    - CPU 密集型：计算、加密 → 线程数 ≈ CPU 核心数
>    - I/O 密集型：等网络/磁盘 → 线程数可以更大
> 3. 根据你的判断，`corePoolSize` 设多少？
> 4. `maxPoolSize` 和 `queueCapacity` 怎么搭配？
>    - maxPoolSize 大 + queueCapacity 小 → 倾向于开新线程
>    - maxPoolSize 小 + queueCapacity 大 → 倾向于排队
>    - 你的场景倾向哪种？

> 📚 **基础补充 — I/O 密集型 vs CPU 密集型**：

| 类型 | 特点 | 线程数建议 |
|------|------|-----------|
| CPU 密集型 | 主要耗 CPU（计算、加密） | CPU 核心数 + 1 |
| I/O 密集型 | 主要等网络/磁盘（数据库、API 调用） | CPU 核心数 × 2 或更多 |

### 拒绝策略（队列满了怎么办？）

| 策略 | 行为 | 适用场景 |
|------|------|---------|
| `CallerRunsPolicy` | 调用方自己执行（降级为同步） | ✅ 推荐：不丢任务 |
| `AbortPolicy` | 抛异常 | 严格保证不超载 |
| `DiscardPolicy` | 静默丢弃 | ❌ 不推荐 |

> 🧠 **面试话术**：用 `CallerRunsPolicy`——"这是优雅降级，极端情况下自动退回同步模式，保证不丢数据"。

## 四、你的任务

### 子任务 1: 配置线程池参数（AsyncConfig.java）

**文件**: `config/AsyncConfig.java`（骨架已生成）

**目标**: 配置一个适合 Neo4j 写入场景的线程池。

> 🧠 **引导**：你需要创建一个 `ThreadPoolTaskExecutor` Bean，设置以下属性：
> - `corePoolSize`、`maxPoolSize`、`queueCapacity`、`keepAliveSeconds`
> - `threadNamePrefix`（建议 `"neo4j-async-"`，出问题在日志里一眼认出来）
> - `rejectedExecutionHandler` → 你选哪个策略？
> - `initialize()` ⚠️ **必须调用**，否则配置不生效！
>
> 💡 线程名前缀很重要——当线程池满了出问题，你在日志里靠线程名就能定位是哪个线程池的问题。

### 子任务 2: 把 Neo4j 写入改成异步

**文件**: `neo4j/service/ConversationAnalysisService.java`（已有引导注释）

> 🧠 **引导**：
> 1. `@Async` 注解加在方法上就行了吗？需要指定线程池名字吗？
> 2. 如果加 `@Async`，调用方需要改吗？（提示：不需要，Spring 代理透明处理）
> 3. 异步方法返回 `void` 够吗？什么时候需要 `CompletableFuture<Void>`？
>    - void: 调用方不需要知道结果 → 你的场景用 void 就行
>    - CompletableFuture: 调用方需要等结果或处理异常
> 4. **关键问题**：为什么同类方法调用 `@Async` 不生效？
>    （Spring AOP 和 @Async 都用动态代理——`this.method()` 绕过了代理！）
